While at the University of Edinburgh I got to take a class in Modern Cryptography. Most of this class revolved around proving security around computational hardness. We worked with PRGs, PRFs, and how to reduce modern cryptographic protocols to computationally hard problems like the Decisional Diffie-Hellman assumption. In the last week there was a brief introduction to Zero Knowledge Proofs and proving security with leakage instead of hardness.

Below is a reduction of how RSA OAEP is in fact IND-CPA secured by the RSA Assumption: the hardness of finding $e$-th roots modulo $N$. I thought this would be interesting because in class we only went as far as black box reductions. This is a knowledge extraction reduction which is different because compared to black box reductions where D simply outputs whatever A outputs, D has to use the results of A to extract something else and keeps track of A's queries.

The RSA-OAEP Protocol

Generation
  1. Choose two large primes $p$ and $q$
  2. Compute $N = pq$
  3. Compute Euler's totient $\varphi(N) = (p-1)(q-1)$
  4. Choose $e$ such that $1 < e < \varphi(N)$ and $\gcd(e, \varphi(N)) = 1$
  5. Compute $d = e^{-1} \bmod \varphi(N)$
  6. Output public key $\mathsf{pk} = (N, e)$ and secret key $\mathsf{sk} = (N, d)$
Enc(pk, m) → c
  1. Compute $X = m \oplus G(r)$ and $Y = r \oplus H(X)$ where $r$ is a random nonce
  2. The padded message is $\mu = (X \| Y)$
  3. Output $c = \mu^e \bmod N$
Dec(sk, c) → m
  1. Recover $\mu = c^d \bmod N$
  2. Split into $X$ and $Y$, then recover $r = Y \oplus H(X)$
  3. Recover $m = X \oplus G(r)$

IND-CPA Security Game Rules

Set Up

The challenger runs Gen to produce a public/private key pair (pk, sk). Like in the real world, the adversary knows the encryption scheme and the pk, the only thing kept secret is sk. The adversary outputs two messages $m_0$ and $m_1$ of equal length. The challenger picks a random bit $b \in \{0, 1\}$, encrypts $m_b$, and returns the challenge ciphertext $c^*$.

Query Phase

Similar to how you can submit any message of your choice and encrypt it with someone's public key, the adversary can submit any message of their choosing to an oracle $\mathcal{O}$ who will encrypt them and return the cipher text. The only thing we are not allowed to encrypt in this oracle is $m_0$ and $m_1$.

Challenge Phase and Win Condition

The adversary can continue making encryption queries as long as they occur within PPT. Then outputs a guess $b'$. The goal is to guess which $c^*$ is the cipher text to $m_b$.

The scheme is IND-CPA secure if for every PPT adversary, their advantage over random guessing is negligible:

$$\Pr\!\left(\mathsf{PrivK}^{\mathsf{CPA}}_{\mathcal{A},\Pi}(1^n) = 1\right) \leq \tfrac{1}{2} + \mathsf{negl}(n)$$

Now we can prove that this is in fact IND-CPA secure through a formal reduction.

Assumptions

Assume $\exists$ PPT adversary $\mathcal{A}$ that breaks IND-CPA of RSA-OAEP with non-negligible advantage:

$$\Pr\!\left(\mathsf{PrivK}^{\mathsf{CPA}}_{\mathcal{A},\Pi}(1^n) = 1\right) \geq \tfrac{1}{2} + h(n) \text{ for some non-negligible } h$$

Assume the RSA problem is hard — no PPT distinguisher $D$ can invert RSA with non-negligible advantage:

$$\Pr\!\left(D(N, e, y) = x : y = x^e \bmod N\right) \leq \mathsf{negl}(n)$$

Construct a Distinguisher $D$ that receives an RSA challenge $(N, e, y)$. $D$ wants to find an $x$ such that $x^e \equiv y \pmod{N}$. To do this, $D$ will use $\mathcal{A}$ which we assume can break RSA-OAEP. $\mathcal{A}$'s goal is to win the IND-CPA game written earlier.

Constructing Distinguisher D

$D$ receives an RSA challenge $(N, e, y)$ where $y = x^e \bmod N$ and must recover $x$. $D$ uses $\mathcal{A}$ as a subroutine.

  1. $D$ forwards the public key $(N, e)$ to $\mathcal{A}$. $\mathcal{A}$ responds with two messages $m_0$ and $m_1$.
  2. $D$ simulates the random oracles $H$ and $G$. For any fresh query, $D$ picks a uniform random string, records it in G-List or H-List, and returns it. For repeat queries, $D$ returns the same value.
  3. $D$ sets the challenge ciphertext $c^* = y$ and forwards it to $\mathcal{A}$ as the encryption of $m_b$. $\mathcal{A}$ runs, making oracle queries throughout, which $D$ answers via its simulated oracles.
  4. $D$ keeps a complete log of all queries $\mathcal{A}$ makes to $H$.

Now for the fun part, for $\mathcal{A}$ to distinguish $c^*$ with a non-negligible advantage, $\mathcal{A}$ must eventually query the random oracle $H$ on the correct intermediate value used during OAEP padding. This is referred to as the AskH event.

The intuition here is a little tricky but OAEP hides the randomness used during encryption through the relationship: $Y = r \oplus H(X)$

Without querying $H(X)$, the adversary cannot recover the randomness $r$ or learn anything meaningful about how the message was padded before RSA encryption. Therefore, any adversary that distinguishes the challenge ciphertext from random must query $H$ on this value with non-negligible probability.

For the sake of time, let's assume that $\Pr[\mathsf{AskH}] \geq h(n) - \mathsf{negl}(n)$ (formally this is another proof).

$D$ scans its H-List to find the oracle query corresponding to the value used during OAEP padding of the challenge ciphertext. Once this value is identified, $D$ can reconstruct the padded message $\mu$ that satisfies $y = \mu^e \bmod N$. This directly gives the RSA preimage, so $D$ outputs $x = \mu$.

  • World 0: $y$ is a valid RSA ciphertext of $m_b$. $\mathcal{A}$ sees a properly distributed challenge and wins with probability $\geq \tfrac{1}{2} + h(n)$.
  • World 1: $y$ is a uniform random element of $\mathbb{Z}_N$ with no relation to $m_0$ or $m_1$. $\mathcal{A}$ wins with probability exactly $\tfrac{1}{2}$ cause it can do no better than just guessing.

If $\mathcal{A}$ distinguishes World 0 from World 1 with non-negligible advantage $h(n)$, it must have queried $H$ on $s^*$, and $D$ recovers $x$ from that query log with the same non-negligible probability. This contradicts the original RSA hardness assumption we made. If $D$ is able to do this then RSA is not computationally hard, and we have a contradiction. Therefore no such $\mathcal{A}$ exists, and RSA-OAEP is IND-CPA secure.

And that's it! I would not call this a formal proof by any means as I definitely left out a few lemmas such as including the probability of oracle collisions, but I think this encapsulates the general idea.

To go a step further (which I did not do :D), you can also prove that RSA-OAEP is IND-CCA secure which is chosen as cipher text secure. This game functions the exact same way as IND-CPA except the adversary also gets access to a decryption oracle where it can decrypt any cipher texts, and provides a more stricter security definition because the adversary now has more power.
